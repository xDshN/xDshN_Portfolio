# Портфолио Андрея Варнавского

Полный исходный проект сайта, подготовленный для автоматической публикации на GitHub Pages.

В архиве уже находятся:

- весь код сайта;
- десктопная и мобильная версии;
- фотографии, графика и четыре видео;
- favicon и метаданные страницы;
- автоматический сценарий публикации `.github/workflows/deploy-pages.yml`.

Этот облегчённый комплект специально подготовлен для загрузки через браузер GitHub: в нём меньше 100 файлов, а каждый файл значительно меньше 25 МБ.

## Самый простой способ опубликовать

1. Создайте на GitHub новый репозиторий. Например, `andrey-broadcast-portfolio`.
2. Распакуйте архив, откройте получившуюся папку, нажмите `Ctrl+A` и загрузите в корень репозитория **её содержимое**, включая папку `.github`. Сам ZIP загружать не нужно.
3. Убедитесь, что основная ветка называется `main`.
4. На странице репозитория откройте `Settings` → `Pages`.
5. В блоке `Build and deployment` выберите `Source: GitHub Actions`.
6. Откройте вкладку `Actions` → `Deploy portfolio to GitHub Pages` и нажмите `Run workflow`, если публикация не стартовала автоматически.

Через несколько минут сайт будет доступен по адресу:

```text
https://ВАШ-ЛОГИН.github.io/НАЗВАНИЕ-РЕПОЗИТОРИЯ/
```

Если репозиторий называется `ВАШ-ЛОГИН.github.io`, адрес будет короче:

```text
https://ВАШ-ЛОГИН.github.io/
```

Путь к репозиторию определяется автоматически: изображения, видео, favicon и файлы Next.js будут работать при любом названии репозитория.

## Загрузка через командную строку

Создайте пустой репозиторий на GitHub, откройте терминал в этой папке и выполните:

```bash
git init
git add .
git commit -m "Publish portfolio"
git branch -M main
git remote add origin https://github.com/ВАШ-ЛОГИН/НАЗВАНИЕ-РЕПОЗИТОРИЯ.git
git push -u origin main
```

После этого включите `GitHub Actions` в `Settings` → `Pages` по инструкции выше.

## Локальный запуск

Потребуется Node.js 22 или новее.

```bash
npm ci
npm run dev
```

Откройте `http://localhost:3000`.

Для проверки финальной статической сборки:

```bash
npm run build
npx serve out
```

## Как обновлять сайт

Редактируйте файлы в `app/` и ассеты в `public/assets/`. После каждого `push` в ветку `main` GitHub Actions сам пересоберёт сайт и заменит опубликованную версию.

Основные файлы:

- `app/page.tsx` — тексты, карточки, проекты, интерактивность;
- `app/globals.css` — вся визуальная стилистика и адаптив;
- `app/layout.tsx` — заголовок, описание и favicon;
- `public/assets/` — фотографии, видео и иконки;
- `next.config.ts` — статический экспорт и поддержка подпути GitHub Pages;
- `.github/workflows/deploy-pages.yml` — автоматическая публикация.

## Важно

- Не загружайте `node_modules` и `.next` — они не нужны.
- Не удаляйте `.nojekyll`, `.github/workflows/deploy-pages.yml` и `next.config.ts`.
- Все медиа входят в проект; отдельный CDN или сервер не требуется.
- Сайт полностью статический: база данных и серверные функции для GitHub Pages не нужны.
